# @modusone/design

The Modus One design system, packaged. Consumed by every Modus One app.

## Two themes

**Deep Field** is the corporate theme (site, decks, documents, finance and compliance tools): the top-level
`color`, `font`, `size` and `motion` in `src/tokens.json`, built to `dist/modus-one.css` as `--m1-*`.
**Horizon** is the consumer theme: `horizon` in the same file, built to `dist/horizon.css` as `--hz-*`.
Paper is Horizon's light mode and Forest its dark. They share the lens geometry and `PATTERNS.md`, and
nothing else: never use an `--m1-*` colour or typeface in a Horizon app, or the reverse.

## The one rule

**`src/tokens.json` is the only place a colour, font stack, size or motion token is ever edited.**
Everything in `dist/` and `tailwind.cjs` is generated by `scripts/build.mjs`. Never hand-edit
a generated file — the next build overwrites it, and `npm test` will fail on the drift.

Non-token CSS (the `.m1-*` primitives) lives in `src/primitives.css` and is concatenated
into the output as-is.

## Patterns

`PATTERNS.md` is the interaction layer: how choices, tables, figures, planning, undo and notices behave
in every Modus One app. It ships in the package and each app imports it into its own `CLAUDE.md`. A new
pattern built in any app is described there in the same change, with its adoption row; a change to a
pattern is a release like a token change.

## After any change

```bash
npm run build && npm test
```

`npm test` enforces, for both themes: every text token clears WCAG AA (4.5:1) on its own ground,
the spring behaves as its theme says (Deep Field never overshoots, Horizon overshoots slightly), and
`dist/` matches `src/tokens.json`. If you change a colour and the contrast test fails,
**fix the colour or change the documented floor deliberately — don't weaken the test.**

Then tag a release so consuming apps upgrade on purpose, not by accident:

```bash
git tag v1.x.0 && git push --tags
```

## Design rules Deep Field encodes

The full brand system — rationale, iconography, voice, the deck spec — is in the
`modus-one-brand` skill (formerly `modus-one-deck`). Read it before adding anything new here. Live reference:
modusone.io, which is the source of truth. If this package and the site disagree, the
site wins.

- Dark is the default. Light is a `[data-theme="light"]` override, not a second design.
- Three typefaces, each with one job. Never a fourth. Newsreader is *italic only* — never
  upright, never bold.
- Three accents, each with one job: `spark` is the voice (one italic phrase, the lens dot),
  `accent` is structure (numerals, rules, focus), `accent2` is labels only (≤13px mono).
- Two signal tokens, `positive` and `negative`, colour figures and statuses by meaning in
  apps. They share spark/accent hues deliberately; they are never decoration.
- Hairlines separate sections, not boxes. Cards get `bg2` + a 2px terracotta top rule —
  no border, no shadow, no rounding past 8px.
- The logo is `modus` regular + `one` bold. Mark is r20 ring at full ink, stroke 2, dot r6
  in spark. Don't substitute a pattern glyph for it.

## Don't

- Don't add a component here speculatively. This package holds what more than one app
  actually needs. One-off layout belongs in the app.
- Don't add a dependency. It ships CSS and a JSON file; it should stay installable
  anywhere with no build chain.
- Don't introduce a typeface or a colour outside a theme's token set. Deep Field has three faces, Horizon two.

## Design rules Horizon encodes

- Light is the default. Forest is the `[data-theme="dark"]` override.
- Two colours carry meaning: `lead` (act, here, done) and `signal` (needs you). No third accent.
- Filled `surface` cards at 20px, 12px fields, pills. No shadows, no gradients.
- Display is sentence case Bricolage 800 and ends with a full stop.
- The spring overshoots slightly; `npm test` bounds it between 0.5% and 6%.
- The logo is the same lens with ring stroke 3 and a Bricolage wordmark, `modus` 500 + `one` 800.
